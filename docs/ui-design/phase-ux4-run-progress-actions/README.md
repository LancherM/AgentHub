# UX4 Run Progress And Actions

Design artifact for `docs/interaction-optimization-roadmap.md` phase UX-4.

The mock shows the intended desktop run-card hierarchy:

- active runs expose a compact stage rail, last activity, and wait state;
- terminal runs collapse toward review actions instead of raw event streams;
- primary actions are ordered around review, compare, and continuation;
- comparison is visible only when a terminal same-task or same-turn peer exists;
- raw events remain behind the inspector/audit path by default.
